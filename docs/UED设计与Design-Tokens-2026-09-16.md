## 1. 规范范围与优先级

1. 本文负责视觉取值、组件结构与状态表达；PRD负责业务、默认值、字段校验、交互分支及验收。两者共同使用，不能只按截图开发。
2. “已映射”表示在当前主题或CSS找到明确配置，不等于全部页面视觉验收通过；“目标”表示需要实施和验收，不能当作已完成。
3. 代码依据：[uedTheme.js](../src/uedTheme.js)、[ued.css](../src/ued.css)及页面局部样式。局部样式覆盖主题时，需核对最终计算样式，不能仅对照主题对象。
4. 正式默认值与交互以PRD第1.2、2—10章为准。发现冲突时登记差异并统一公共组件，不逐页新增补丁。
5. 本次只更新设计规范，不改变运行代码、不重新部署GitHub Pages。旧文档中的逐轮验收结论不代表本次已重测。

### 1.1 设计原则

1. 一个页面一条主阅读线：核心依据在当前页，完整依据进入抽屉。
2. 操作反馈就近：字段错误在字段下、分组错误在组内、整体请求失败在页面或弹层内。
3. 普通说明安静可读：灰字、无底色、无左色条；真实阻断错误不能因视觉降噪被隐藏。
4. 已完成是执行状态，不代表内容全部通过；状态同时用文字和必要图标表达，不能只靠颜色。
5. 可见数量和状态来自真实当前范围；未知用“—/未记录”，不以0、100%或默认值填补。
6. 不在面向用户的页面反复添加Demo免责声明、内部技术说明；演示性质、真实检测边界写在开发/验收文档中，不把演示测试当作真实效果验收。

## 2. Token分层与来源

推荐命名层级为基础值ref → 语义sys → 组件comp。当前工程已使用Ant Design主题及CSS变量，**不要求为了命名重写全部代码**；新增样式优先引用现有变量。语义名称是设计职责，不代表同名变量已经存在。

| 层 | 责任 | 接入方式 |
| --- | --- | --- |
| 基础 | 色值、4px间距尺度、字号、圆角 | 主题入口统一管理，不散落业务条件中。 |
| 语义 | 正文、次级信息、错误、边界、选中 | 映射uedTheme.token或ued.css变量。 |
| 组件 | 表头、卡片标题、输入行、报告指标 | 公共组件/组件主题优先；局部例外命名限定作用域。 |
| 状态 | hover/focus/disabled/loading/error | 保留组件库语义；补丁不能覆盖掉校验、焦点及禁用行为。 |

| 项 | 目标值/要求 | 状态 |

### 4.3 响应与专业画布

1. 普通任务单主列；依据摘要在输入后，完整依据用抽屉，不再增加常驻长侧栏。
2. ≤1000px表单按现有CSS转单列；其他宽度按容器而非整屏宽度决定双列。统计卡可换行，表格允许局部横滚。
3. 文档专业编辑器例外：左224px、画布弹性、右300px；≤1280px为190/弹性/250；≤900px为170/最小240/220并允许工作区横滚。
4. 画布栏间距12px、画布内距14px，工作区最低240px；两侧可独立滚动，普通表单不照搬三栏滚动。
5. 抽屉和弹窗不得超过视口；宽报告抽屉使用视口内最大可用宽度，避免把完整规则表压到窄栏。具体宽度按组件内容验收，不全局写死720px。
6. 至少验证1366×768、1920×1080与125%缩放；小于768px以可读和核心操作可达为目标，不宣称已完成移动端设计。

## 5. 控件与状态规范

表内编号是逐项实现要求。详细业务校验见PRD，不在视觉层重定义阈值。

### 6.2 任务配置及依据

1. 页面依次组织任务信息、输入、核心依据摘要、业务配置、结果写入及自动复检；结果写入始终独立卡片。
2. 摘要不挤成一句话：首行标题和“查看模板规则/完整报告”；下行指标分组，模板名称独立或留足间隔，不带版本号。
3. 质检摘要显示启用质量规则数、标签规则数、依据模板；抽屉展示模板规则，不提供二次规则/字段/质检合格阈值选择。
4. 增强/扩增选择报告后显示整体分、有效判定覆盖率、已检查/全部及相关决策统计；未选时用轻提示而非一张巨大空报告。
5. 当前页不保留“任务配置/任务依据”独立tab。抽屉关闭保留表单数值、目标及滚动。
6. 配置快照在详情基本信息中默认展开；旧值未记录时不填当前默认值。主阅读区显示模板名，不露版本后缀。

### 6.3 增强基础样本与方案

1. 样本卡上层显示全部/已检/未检；中层显示全规则通过数、可筛选数、质量分中位数；下层为选样方式与当前选中构成。
2. 默认仅通过样本；按分模式才出现滑条、输入框和使用中位数。滑条范围来自有效池最小/最大分，同分禁无意义拖动。
3. 抽检允许显式纳入未检，默认不选；“已检A＋未检B”与选中总量相邻，未检无质量分且不受阈值限制。
4. 增强数量上限放本卡，说明低于基础数随机抽、高于基础数重复采样生成变体，不命名为额外一套“目标生成数量”。
5. 文档图像/语义/背景三个折叠卡，标题仅已选数；图像表含方式、说明、单项强度，自定义规则表含名称、增强Prompt、操作。
6. 常驻文字：“语义规则全部执行，图像效果随机组合，背景方式每次任选一种。”对话/时序布局同骨架，但不照搬不适用的图像/背景方式。
7. 不出现隐私增强、标注同步开关；一致性由处理能力保证并质检，不转嫁成用户可取消选项。

### 6.4 定向扩增

1. “规则不通过”在左且默认选中，“标签分布不足”在右；无增强基础样本卡、阈值滑条。
2. 规则行显示失败率/失败数/推荐与计划；标签行显示数量、通过/失败/未知、不通过率、推荐与计划。
3. 维度名是标题，不能勾选；枚举行才可选。系统自动和用户自定义分区，各维度平铺。
4. 非零基数填计划新增百分比并即时显示整数数量；零基数输入条数。推荐提示展示公式及本行代入数，不覆盖用户已改计划。
5. 底部仅显示已选目标数和计划新增合计；抽检常驻说明范围，不能把抽检未覆盖写成全量缺失。

### 6.5 质检报告

| 层级 | 展示内容 | 约束 |
| --- | --- | --- |
| 报告头 | 报告选择、版本/范围、下载JSON | 同报告各入口同源；模板试运行下载在卡片title右侧。 |
| 核心指标 | 整体分、有效判定覆盖率＋info | 中性卡片，单位与分母明确；无有效结果为“—”。 |
| 执行统计 | 已检查/全部、已处理、成功完成、异常 | 状态不等于质量结论，不放大红底。 |
| 规则结果 | 按组折叠、搜索、状态数量与钻取 | 无法判定表头旁info；非零数字才是链接。 |
| 标签覆盖与分布 | 自动/自定义分区、完整维度卡片 | 零枚举保留；未配置、未返回、真实0分开。 |
| 执行异常Badcase | 放在标签区域之后 | 内容不通过不作为执行异常；明细可追溯。 |

1. 有效判定覆盖率tooltip：“有效判定覆盖率 =（通过+不通过）÷（通过+不通过+无法判定），按样本×规则计数；不适用、未抽中、未执行另列。”
2. 无法判定tooltip：“输入不足或检测执行异常，暂不能判断通过与否；不计入规则通过率，计入有效判定覆盖率分母。”
3. 标签卡按容器宽度换行，标题为维度名、右侧覆盖率，下行显示已覆盖/全部与已分类/未知，表内枚举数量和分布条。
4. 规则明细与样本证据按PRD用抽屉/必要下一层，不为旧线框强制跳转成另一套报告页面。
5. 普通常规报告不显示隐私检测；模板发布、上传发布在各自检查区展示。加载失败不能降级成全0报告。

### 6.6 数据中心与上传发布

1. 数据集详情包含基本信息、版本列表、最新上传任务卡片；版本表不选中、不高亮。
2. 上传卡片title处提供版本切换，默认最新上传任务；不要增加CHECK-ID切换框。
3. 上传发布步骤为文件检查→隐私/安全→发布；检查中、待处理、发布中、成功有不同状态文案。
4. 命中明细按上传包分组，包级错误与样本错误分开；数量去重，必要证据按权限查看，默认不直接铺开敏感原文。
5. 操作为“删除命中样本并发布”“配置脱敏并发布”“重新上传”；脱敏方案必须说明同时删除安全/结构命中样本，确认后处理、复检、发布。
6. “重新上传”进入编辑页，不只关闭当前弹层；处置失败保留输入和原因。版本详情基本信息/数据预览/质检报告按PRD保留，不因旧线框重命名导航。

## 9. 交付与验收

1. **视觉回归范围**：三类模板编辑/试运行；四类任务创建/详情；数据集版本报告；上传待处理/发布；API模型增删。每项保留相同视口的截图对照。
2. **控件矩阵**：默认、hover、focus、选中、禁用、loading、error、success；不适用写原因，不因默认态好看省略其他状态。
3. **布局检查**：标题与按钮对齐；新增模型在列表下方；无竖排按钮；卡片间距一致；长说明可读；固定栏不遮校验错误；标签全维度可见。
4. **报告检查**：各入口共享指标、info文案、规则分组与异常顺序；不能只修任务详情而漏数据集/增强/扩增。
5. **交互检查**：编辑取消、弹层关闭焦点、保存失败、切换依赖、旧数据回填、未知统计、错误恢复均按PRD验收。
6. **效果与性能**：本文件不替代PRD第13章。图像真实感、语义保真、检测准确率、并发与大文件必须独立评测。
7. **变更治理**：新增或改token同时更新主题/共享CSS、本文件、受影响截图；新增UI默认值同时更新PRD。未实施要求登记差异，禁止再用“最新一节覆盖所有旧文”长期堆叠冲突规范。
